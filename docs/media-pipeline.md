# Медиа-слой: постер → видео

Как сайт показывает фоновое видео: сначала резкий кадр из HTML, затем тот же кадр
начинает двигаться, и переход не виден. Документ описывает устройство, сборку
файлов, выкладку и эксплуатацию. Если что-то из описанного расходится с кодом, прав код.

## Идея в двух абзацах

Посетитель сначала видит **постер**: `<picture>` приходит в HTML, у него заданы
размеры, он не ждёт ни JS, ни видео. Постер вырезан из **нулевого кадра готового
MP4**, поэтому когда видео начинает играть, оно стартует ровно с той картинки,
которая уже на экране. Видео лежит **под** постером в разметке и всегда может
вернуться к нему, поэтому чёрного кадра между состояниями нет по построению.

Видео проявляется не раньше, чем выполнены три условия: источник декодировал
первый кадр, в буфере есть запас (1,5–3 с, по умолчанию 2), а браузер подтвердил
через `requestVideoFrameCallback`, что показан кадр _после_ нулевого, то есть
картинка действительно движется. Только тогда включается CSS-переход прозрачности
на 600 мс (`--motion-media`, кривая `--ease-out-expo`). Любая ошибка оставляет постер.

## Состояния

```
POSTER → LOADING → DECODED → SAFE → VISIBLE
                                  ↘ (остановка) → LOADING (запас ×1,5, до 3 раз) → FAILED
OFF     prefers-reduced-motion, Save-Data, 2g: постер, ни одного запроса видео
FAILED  ошибка источника, автозапуск отклонён навсегда, четвёртая остановка: постер
```

`data-sm-state` на корне поверхности отражает состояние; CSS открывает видео только
в `visible`.

## Сборка файлов (вне VDS)

Кодирование выполняется локально, в CI или отдельным заданием. На VDS его запускать
не нужно и не следует. Нужны `ffmpeg` ≥ 5 с libx264 и `sharp` (уже есть в `node_modules`).

```bash
# 1. Найти склейки, чтобы выбрать начало и конец превью по границам планов
node scripts/media/build-web-video.mjs --master master.mp4 --detect-cuts --from 0 --to 20

# 2. Собрать набор: desktop MP4 + mobile MP4 + постеры AVIF/WebP/JPEG + запись в манифест
node scripts/media/build-web-video.mjs --key showreel --master master.mp4 \
  --hls 83ad0e8e-c614-46fd-8324-2c26659ad721 --start 0 --end 8.04 --out public/media

# 3. Сравнить CRF и SSIM, ничего не записывая
node scripts/media/build-web-video.mjs --master master.mp4 --end 8.04 --candidates 24,26,28
```

Мастер может быть путём или `http(s)`-ссылкой.

Что гарантирует скрипт:

- десктоп 1920×1080, мобайл 608×1080 (вертикаль 9:16), H.264 High, `yuv420p`, без аудио,
  `+faststart`, GOP не длиннее 4 с (склейки монтажа получают свой IDR), цветовые теги bt709;
  после кодирования файл проверяется (faststart, кодек, размеры), иначе сборка падает;
- постер вырезается из **готового** MP4, а не из мастера: кадры совпадают до пикселя;
- AVIF → WebP → JPEG, две ширины на вариант (для экранов DPR 1 и 2);
- хеш содержимого в имени файла, значит `immutable` на год безопасен;
- в манифест попадают размеры, байты, длительность, кодек, средний цвет кадра и
  крошечный размытый `lqip` (фон до загрузки постера).

Окно превью (`--start`, `--end`) задаётся при сборке и хранится в манифесте; границы
лучше выбирать по склейкам из `--detect-cuts`, чтобы превью не обрывалось посреди плана.

## Выкладка

Две дорожки, обе без пересборки образа.

1. **Hero из git** (`public/media`). Лежит в репозитории (около 5 МБ), попадает в образ
   фронтенда и отдаётся Next.js. nginx проксирует на него, если файла нет в томе.
2. **Большие наборы вне git** (превью проектов, десятки МБ). Файлы кладутся в
   `/var/www/savage-media/` на VDS; compose монтирует этот каталог в nginx как
   `/srv/media` (только чтение). nginx отдаёт их сам, с `Range`/206 и вечным кешем.
   Выкладка идёт по правилу **«сначала файлы, потом манифест»**: пока записи в манифесте нет,
   поверхность работает как раньше, поэтому порядок безопасен.

Поведение `location ^~ /media/`:

- `^~` обязателен: иначе regex статики (`.webp`, `.jpg`) перехватит постеры и отдаст
  их с 30-дневным кешем;
- `Cache-Control: public, max-age=31536000, immutable` **без** `always`: nginx и так ставит
  заголовок на 200/206/304, а `always` закрепил бы на год ещё и 403/404/5xx (например,
  если манифест выложили раньше файлов);
- `Range` обрабатывается статикой nginx. Safari не проигрывает MP4 без 206;
- в `@media_frontend` заголовок кеша не подменяется: успешный ответ фронтенда несёт
  `immutable` из `next.config.ts`, а его 404 остаётся `no-store`.

Правила nginx стережёт `infra/nginx/__tests__/media-routing.test.ts`.

### Откуда берутся файлы

`lib/media/config.ts` держит две независимые базы, чтобы их можно было переносить по отдельности:

| Переменная                          | По умолчанию                                               | Для чего                  |
| ----------------------------------- | ---------------------------------------------------------- | ------------------------- |
| `NEXT_PUBLIC_WEB_MEDIA_BASE_URL`    | `/media` (тот же origin)                                   | постеры и короткие MP4    |
| `NEXT_PUBLIC_STREAM_MEDIA_BASE_URL` | `https://<NEXT_PUBLIC_BUNNY_CDN_HOSTNAME>` (прокси `/cdn`) | HLS и превью Bunny        |
| `NEXT_PUBLIC_HLS_PROGRESSIVE`       | выключено                                                  | флаг hls.js `progressive` |

Те же файлы можно выложить на отдельный домен или российский CDN: достаточно сменить
`WEB_MEDIA_BASE_URL` и пересобрать. Прокси `/cdn` перед Bunny остаётся как есть.

## Контракт поверхности (`data-sm-*`)

Корень поверхности рендерит `MotionSurface`; загрузчик читает атрибуты:

| Атрибут                    | Смысл                                                                                  |
| -------------------------- | -------------------------------------------------------------------------------------- |
| `data-sm-src-d` / `-m`     | URL MP4 для десктопа и мобайла: скачивается только нужный                              |
| `data-sm-mq`               | медиазапрос мобильного варианта (`(max-width: 767px)`)                                 |
| `data-sm-stream`           | id Bunny, если MP4 нет: HLS подключает `StreamDriver`                                  |
| `data-sm-load`             | `eager` (hero) или `near` (карточки)                                                   |
| `data-sm-play`             | `auto`, `hover` (мышь: наведение; тач: видимость), `hover-only` (на таче движения нет) |
| `data-sm-only`             | медиазапрос: блок оживает, только пока он выполняется                                  |
| `data-sm-hover-scope`      | селектор предка, над которым ловится hover (карточка целиком)                          |
| `data-sm-buffer`           | запас буфера, 1,5–3 с                                                                  |
| `data-sm-hero`             | hero: грузится сразу, не входит в лимит превью                                         |
| `data-sm-after="hero"`     | не начинать, пока hero не определился                                                  |
| `data-sm-hold-until`       | селектор: не показывать, пока такой элемент в DOM (заставка), но не дольше 1,1 с       |
| `data-sm-active`           | `off`: блок закрыт другим (стопка карточек), не грузить и не играть                    |
| `data-sm-native`           | `1`: HLS идёт нативно (Safari/iOS); ставит драйвер, нужен для «прогрева» без `preload` |
| `data-sm-alt` (на `<img>`) | `url\|url`: запасные постеры, если основной не загрузился (кадр Bunny ещё не создан)   |

Нет первого кадра за 12 с (манифест HLS не ответил, сеть оборвалась без ошибки): поверхность
остаётся постером и освобождает сеть. Системная пауза видимого видео (экономия заряда, звонок)
сразу снимается; если играть не дают, поверхность возвращается на постер.

Лимиты: одновременно не больше двух превью без hero; карточка вне экрана не получает
`src`; намерение наведения подтверждается за 130 мс; выгрузка карточки без слота идёт с задержкой.

## HLS: одна фабрика

`new Hls(...)` создаётся **только** в `lib/media/hls-controller.ts` (страж:
`lib/media/__tests__/guards.test.ts`). Фабрика:

- выбирает стратегию: нативный HLS для Safari/iOS, hls.js (MSE) для остальных, иначе постер;
  по WebKit, а не по `canPlayType`: Chrome 124+ отвечает «maybe», но надёжно HLS нативно не играет;
- режим `background` (карточки и фоны без MP4) фиксирует уровень под размер контейнера и DPR (потолок 1080),
  режим `player` (контролы, весь фильм) оставляет обычный ABR;
- стартует после `MANIFEST_PARSED`, ограничивает буфер, повторяет сетевые и медиа-ошибки с backoff,
  останавливает загрузку в скрытой вкладке, освобождает всё в `destroy`;
- hls.js грузится динамическим импортом: страницы только с MP4 его не получают.

Полный фильм (showreel в `FullScreenVideoPlayer`, страница проекта) идёт по HLS
с обычным ABR. Hero и превью HLS не используют.

### `progressive`

Флаг hls.js `progressive` включается переменной `NEXT_PUBLIC_HLS_PROGRESSIVE=true`.
Сравнение на реальном Chrome 154 с H.264 (локальная реплика продакшна: nginx, Next, кеш Bunny; 5 холодных
запусков на ячейку, контейнер 1920×1080, шоурил по HLS, до первого движущегося кадра):

| Сеть             | старый конфиг (ABR)                             | закреплённый уровень | + `progressive`                  |
| ---------------- | ----------------------------------------------- | -------------------- | -------------------------------- |
| 20 Мбит/с, 50 мс | 2014 мс (1080p)                                 | 1733 мс (1080p)      | 599 мс (1080p)                   |
| 8 Мбит/с, 100 мс | 2769 мс (первый кадр 720p, 83 кадра ниже цели)  | 3590 мс (1080p)      | 1114 мс, но 74 кадра ниже цели   |
| 4 Мбит/с, 200 мс | 3797 мс (первый кадр 480p, 57 кадров ниже цели) | больше 6 с           | 2055 мс, но `bufferStalledError` |

`progressive` втрое ускоряет первый движущийся кадр, но на средней и слабой сети ABR
сбрасывает уровень, а на слабой появляются остановки буфера. Hero и превью теперь MP4 и
HLS не используют, поэтому флаг оставлен **выключенным**: он касается только запасного
пути (нет записи в манифесте) и полного фильма. Обновление hls.js 1.6.15 → 1.7.3 на тех
же замерах разницы не дало (в пределах шума), поэтому версия не менялась.

## Телеметрия

Для каждой поверхности загрузчик выпускает один итоговый `report`: когда пришёл
постер, ушёл запрос, декодирован первый кадр, набран запас и когда пользователь впервые
увидел движущийся кадр (**TTFM**, главная метрика). Данные уходят в уже подключённую
Яндекс Метрику параметрами визита (`media`, `media_ttfm_ms`, `media_stall`), не больше
четырёх поверхностей за визит, без новых целей: единственная конверсия сайта остаётся
`production_lead_success`. TTFM пишется корзинами (`lt500` … `gte8000`): так читается без выгрузки.

В консоли для отладки: `window.__sm.events` и метки `performance.getEntriesByType('mark')` с префиксом `sm:`.

## Как добавить поверхность

1. Видео с MP4-превью: собрать набор скриптом, добавить запись в манифест, на странице
   вызвать `mediaSpecsByVideoIds([...])` на сервере и передать `spec` в `MotionSurface`.
2. Видео без превью: `MotionSurface` с `streamId` и `fallbackPoster`. Работает через HLS-драйвер,
   но без гарантий первого экрана: для hero нужен MP4.
3. Для глубоко вложенных клиентских деревьев (лендинг, services) страница кладёт карту
   `{id видео → spec}` в `MediaSpecsProvider`, а `LazyHlsVideo` берёт её через `useMediaSpec`.
4. Hero страницы: `hero` (грузится сразу). Всё остальное в первом экране: `afterHero`.

## Проверка перед выкладкой

```bash
npm run lint && npm run type-check && npm test
node scripts/media/build-boot.mjs --check   # загрузчик не устарел (то же проверяет тест)
```

Что проверяют тесты: машину состояний загрузчика (`lib/media/boot/__tests__`), манифест и
файлы на диске по хешу, чистые функции фабрики HLS, телеметрию, nginx-правила, стражи
(нет `new Hls` вне фабрики, свежесть `boot.generated.ts`, `<video>` без `src` и без `preload`).

Что тесты **не** проверяют, и что нужно открыть руками на реальных устройствах: Safari macOS,
iPhone Safari, Android Chrome, Яндекс Браузер, поведение при Low Power Mode, российские сети.

## Откат

- Выкатить предыдущий образ: файлы `/media` безвредны, это обычные статические файлы.
- Отключить MP4 для поверхности, не откатывая код: убрать запись из `lib/media/manifest.json`.
  Поверхность вернётся к HLS и постеру Bunny.
- Отключить движение везде: удалить `<MediaBoot />` из `app/layout.tsx`. Постеры остаются,
  видео перестаёт стартовать.
